# Objective

Perform the final independent **security and distribution audit** before v1.0 release hardening.

This is not another general functional audit.

Focus on:

- actual Windows package contents;
- source protection;
- licensing/key security;
- customer/owner separation;
- accidental secrets or development material;
- third-party redistribution compliance;
- release staging/inventory;
- installer/distribution risks.

`dist\OandG_Workbench`

and

`dist\Owner Tools`

Do not limit the audit to PyInstaller specs or source rules.

Inspect the actual packaged binaries, archives and bundled files.

**15**

- `.egg`;

# 3. Customer Distribution Contents

Audit `dist\OandG_Workbench` for material that should not ship to customers.

Look specifically for:

- protected source;
- unneeded source code;
- tests;
- test fixtures;
- developer utilities;
- build scripts;
- `.git` or Git metadata;
- scratch files;
- temporary files;
- debug artifacts;
- development databases/projects;
- logs;
- WSD files;
- client/customer data;
- test licenses;
- private keys;
- owner-only material;
- obsolete release files.

Do not flag ordinary runtime Python dependencies merely because they contain Python code. The concern is Workbench proprietary source or inappropriate release material.

---

# 4. Owner Tool Separation

Audit `dist\Owner Tools` separately.

Verify:

- Owner License Manager is not contained in the customer package;
- customer software cannot issue/sign licenses;
- production private keys are not embedded in the customer build;
- private signing material is not accidentally bundled elsewhere;
- owner-trust files cannot grant customer software owner privileges;
- owner-only functionality is meaningfully separated from customer runtime.

---

# 5. Licensing / Key Security

Audit the final licensing implementation and actual packaged binaries.

Review:

- signature verification;
- public-key trust;
- unknown-key rejection;
- expiry;
- time-limited/evaluation behavior;
- machine binding;
- DPAPI;
- clock rollback protection;
- owner licenses;
- production-key setup;
- owner trust;
- imported-license handling.

Pay special attention to:

- `OGW_LICENSE_FILE`
- `OGW_BUILD_TEST_LICENSE`
- `ogw-selftest-*`
- test/build licenses
- owner-trusted-key files

Determine whether any build/test mechanism can be used by a normal customer to bypass licensing.

Do not treat the existence of test infrastructure itself as a vulnerability unless it creates an actual bypass in the distributed software.

---

# 6. User-Data / Runtime Paths

Audit final v0.9.56 path handling, including:

`ogcore/userdata.py`

Verify:

- `%LOCALAPPDATA%\OandG_Workbench` is used appropriately;
- home fallback is safe;
- `%APPDATA%\OandG_Workbench` fallback is safe;
- there is no fallback to working directory;
- there is no unintended executable-directory write;
- there is no unintended project-directory write;
- stripped-environment startup does not weaken licensing or file security;
- preference/state files cannot overwrite program files.

Also verify the final fixes were actually incorporated into the Windows package.

---

# 7. Build / Staging / Release Inventory

Audit:

- `Build_Windows_EXE.bat`
- PyInstaller specs
- staging scripts

# 8. Secrets / Sensitive Material

Search both source and packaged Windows artifacts for:

- private signing keys;
- passwords;
- API tokens;
- credentials;
- connection strings;
- secrets;
- customer information;
- client data;
- unintended local paths;
- personally identifying build-machine information where materially sensitive.

Distinguish:

- public keys;
- harmless test constants;
- ordinary build paths

from actual secrets/security problems.

---

# 9. Third-Party Redistribution Compliance

Audit the third-party software actually bundled in the Windows distribution.

Pay particular attention to:

**segyio 1.9.15 — LGPL-3.0-or-later**

Determine precisely what must accompany the commercial distribution.

Check whether the release currently provides, as applicable:

- copyright notices;
- full LGPL/GPL license text;
- third-party notice;
- source-access information;
- relinking/replacement rights required by the LGPL;
- sufficient information for the recipient to exercise those rights.

Do not assume that a homepage URL or the text `LGPL-3.0-or-later` alone satisfies the obligation.

Also identify any other bundled dependency with redistribution requirements that are not currently satisfied.

Classify legal-compliance findings separately from software vulnerabilities.

---

# 10. Installer Readiness

Review any installer scripts/configuration that already exist.

Determine whether the eventual installer could accidentally:

- include Owner License Manager;
- include private keys;
- include proprietary source;
- include test/development files;
- overwrite user projects;
- install licenses incorrectly;
- require developer/build tools;
- depend on the build machine's paths.

If the final installer has not yet been built, classify these as **Installer Validation Items**, not current package defects.
